## 0.3.0：入口位置改成宿主习惯的做法

用户反馈"论文台在 macOS 上位置不好看"。原来挂的是 `shell.overlay`（`position: fixed` 的右下角气泡），会跟窗口右下角/输入区抢位置，也不是宿主其它管理功能的惯例。

改成 DSH 自带管理页的接法（照 `ui-plugin-manager`、`ui-schedule` 的实现）：

- `ctx.slots.register({ name: 'main', key: 'paper-desk' }, PaperDeskPage)` —— 一整页放在主内容区；
- `ctx.slots.register({ name: 'sidebar.panellist', id: 'paper-desk', order: 40, label: () => '论文台' }, PanelIcon)` —— 左侧边栏一枚 16px 描边图标，点它由侧边栏自己 `selectPanel`；
- 页面根节点从 `position: fixed` 改成 `width/height: 100%` 的 `.pd-page`，自己管滚动；
- 顺手修了弹窗：窗口矮时 `.pd-modal` 之前会顶到视口外、保存按钮点不到，现在弹窗限高、正文滚动、按钮常驻。

## 0.4.0：画布缩放 + 默认排版放宽

用户反馈"图片都在一起挤压"。两个原因：默认三列的纵向间距太小（公式 236px、结果 300px，而带图的节点本身就有 300-340px 高），以及画布没有缩放，画不下时只能硬挤。

- 全局缩放：工具栏 `−` / `百分比`（点击回 100%）/ `+`；`适应` 铺满视口；`聚焦所选` 放大到选中块（上限 150%）；双击节点标题同样聚焦。
- `Cmd/Ctrl + 滚轮` 或触控板捏合以**光标为锚**缩放（0.25x–2.5x）。
- 第一次打开（或导入后首次进入）自动适应窗口；缩放和平移一起存进 `layout`（panX/panY/zoom）。
- 默认排版放宽：三列 x = 40 / 450 / 860，公式行距 280，结果行距 340，原则节点下移到 y=330。
- 顺带修掉一个渲染崩溃：自动适应那段 effect 原本写在 `blocks` 声明之前（TDZ），打开论文会直接白屏。

验证：预览流程新增缩放断言（放大后 scale 变大 → 适应后 ≤ 1.1 → 聚焦后更大），明暗两套 12+ 步零报错。

## 0.4.1：滚轮 / 触控板缩放真的能用

0.4.0 的滚轮缩放**根本没挂上**：那个 `wheel` 监听挂在画布元素上，但画布要等论文读出来才渲染，
effect 的依赖只有 `[applyZoom]`，首次执行时 `canvasRef.current` 还是 null，之后不会重跑 ——
监听器永远没绑上。修法：依赖里加上 `paper`，画布挂载后重新绑定。

同时把交互改成用户直觉：

- 普通滚轮 / 触控板双指 / 捏合 = 以光标为锚缩放（原来是只有 Cmd/Ctrl+滚轮才缩放）；
- `Shift + 滚轮` = 平移，留给"只想挪视图"的场景；
- 鼠标滚轮一档 ~100、触控板一次几像素，用指数映射统一手感。

验证：预览流程新增两条断言 —— 普通滚轮后 scale 变大、Cmd+滚轮后 scale 变小，明暗两套全流程零报错。

## 0.4.2：触控板两指平移

0.4.1 把滚轮一律当缩放，触控板上两指滑动就缩得乱七八糟、没法挪视图。改成按手势分流：

- 捏合（带 ctrl/meta）→ 缩放；
- 两指滑动（像素模式且单次增量 < 25）→ 平移（macOS 惯性滚动也走这条）；

- `Shift + 滚轮` → 水平平移；
- 工具栏多一个「滚轮：自动 / 缩放 / 平移」按钮，按事件特征判断失灵时可强制成单一行为，选择存进 `layout.wheel`。

验证：预览流程新增三条断言 —— 小增量滚轮只改 translate、不改 scale；模式按钮循环 自动→缩放→平移→自动；明暗两套全流程零报错。

## 0.4.3：手势判定粘滞

## 0.7.2：「模型没有返回文本」根治与可诊断化

用户追问「为什么这里要生成 GNN，可以举例子解释一下吗」时，界面报「模型没有返回文本」——原来这句错误把三种完全不同的原因混成一句。

- **主因**：短问答没有关推理。推理模型把思考计入预算，长摘录（7k 字符）下思考吃满预算，正文一个字都吐不出来。
  现在先查 `llm.resolveModelInfo` 的能力，模型声明支持 `off` 时传 `reasoningEffort: 'off'`（dsh-pet 同款做法：
  对没有 reasoning 元数据的模型显式传 effort 会被 dsh-llm 判 `UNSUPPORTED_REASONING_EFFORT`、折叠成空流）；
- **兜底重试**：若仍然只有推理/空流，把检索摘录从 7k 砍到 2k 再问一次；
- **错误可诊断**：区分「finish=length + 只有推理」「没有收到任何正文片段」「上游 abort=已停止」，并给出下一步建议。

验证：新增 `tests/llm-empty.mjs` 6/6（假 llm 流）：正常返回、只有推理时错误含 finish 与推理字数、空流说明、
支持 off 时请求带 `reasoningEffort: 'off'`、不支持时省略该字段、空流不抛异常。

## 0.7.4：追问必空的真正原因（历史消息缺 source）

报错原文：`finish=error，UNKNOWN Cannot read properties of undefined (reading 'replayState')`。

根因在 dsh-llm 的 `forAdapter()`：它遍历请求消息，对 **assistant** 消息读 `message.source.replayState`。
我之前手搓的请求消息只有 `{ role, content }`，没有 `source` —— 于是第一条提问（历史里没有 assistant 消息）正常，
**任何追问**都会在 dsh-llm 内部抛错、被折叠成空流。所以现象是"首问能答，追问必空"。

修法：按 dsh-llm 的 Message 形状构造请求消息 —— `{ id, role, content, source }`，
assistant 的 `source` 是 `{ kind:'model', provider, model }`，user 的是 `{ kind:'user' }`。

验证：`tests/llm-empty.mjs` 新增断言「assistant 历史消息带 source 与 id」（9/9）。

同时把消息复制改成右下角图标（和 DSH 自己的对话一致）：悬停浮现 20px 圆角图标，复制成功换成对勾。

## 0.8.1：原文更清晰 + 面板内缩放 + 系统预览

用户反馈右侧栏的原文"糊"，并问能不能用原生 PDF 查看。

## 0.8.2：裁图按"栏"切 + 正文行定边界；顺手两处 UI

用户反馈：SemaCDR 的结果截图错误、WeaveRec 的原理图截不全。

**根因**：旧算法把"页面上一条图注"当作上边界。双栏论文里两栏的图注在纵向上是交错的，
左栏的 Figure 5 会把右栏 Figure 6 的图注当上界 → 只裁到一条 85px 的横条（还卷进了右栏的正文）。
表格更糟：图注在上、表在下，算法按"图注在上方"去找，结果把图注上方的正文整段裁了进来。

**新算法**（`src/client/pdf.js`）：

1. **按栏**：一条图注的"列"= 与它横向有重叠的所有文本行，裁剪宽度收在这一栏内（不再横跨双栏）；
2. **按正文行定边界**：正文段落的一行通常 ≥60 字符，图内标签/表格单元都很短 ——
   用它当"正文 / 图"的分界，上方最多到最近一行正文，下方同样收在正文第一行之前；
3. **多行图注**：`Table 1: ...` 后面常有 2-3 行说明，先把整块图注算出来，别把续行当正文；
4. **页眉识别**：横跨 70% 页宽且位于页面顶部的行视为 running header，不参与裁剪；
5. **墨迹收紧**：最后按非白像素的包围盒再切一次，去掉四周留白与混进来的残片；
6. **兜底**：精修后不足 60px 时退回"整列"大块，宁可略大也不让图消失。

效果（用用户库里两篇真论文验证）：

| 论文 | 之前 | 现在 |
|---|---|---|
| WeaveRec Figure 5（原理图） | 1062×85 的横条（只有底部一截 + 右栏标题） | 完整框架图（489×322，含全部模块） |
| SemaCDR Table 1（结果） | 图注 + 整张表 + 下方两栏正文 | 只有表格本体（996×804） |
| arXiv:1612.00796 | 7 张 | 7 张（未回退） |

**UI**：删掉工具栏的「原始 PDF」按钮（原文页签仍在右侧栏）；右侧栏左边界加到 `border-l4` 并加一层淡阴影。

注意：已经导入的论文，图是当时裁好存盘的 —— 要看新算法的结果需要**重新导入**。

## 0.8.3：表头不再被切掉（"要完整"）

0.8.2 裁出的 SemaCDR Table 1 少了表头那两行（`Methods / Kitchen→Food / N@5…`）。原因是把图注的
"续行"扩展得太宽，把表头一起吞掉了，于是裁剪起点落到了表头下面。

这样图注整块被排除在裁剪之外，表头则完整保留。

## 0.8.4：裁图泛化（按墨迹取横向范围）+ 手动上传兜底

## 0.9.2：重新裁图"没效果"的真因 + 节点图库只显示本块的图

**"重新裁图点了没效果"**：图确实换了，但 `<img src>` 没变 —— 浏览器复用同一 URL 的位图缓存，
所以界面上还是旧图；删除重导之所以"正常"，是因为新论文换了 id、URL 也变了。

- `assetUrl()` 增加版本参数；换图/上传后 `assetVersion + 1`，所有节点图、放大图、图库缩略图都带上 `&v=`；
- 重新裁图结束后给一条可见提示（成功："已重新裁出 N 张图"；失败：红底错误），以前错误只写进 `error` 状态，
  而论文视图不渲染它 —— 用户什么也看不到。

**节点编辑器只显示本块的图**：以前编辑任何节点都会列出整篇的所有图（像"图都共存"）。现在：

- 该节点没有配图 → 直接列出全部，方便挑一张。

**顺带**：节点里塞满图时也能从图上按住拖动（点击不拖动仍会放大预览；拖动后 250ms 内的 click 会被忽略）。

## 0.9.3：输入法里按 Enter 不再误发送

用户反馈：中文输入法打 "GNN" 时按 Enter 确认候选词，消息被直接发出去了。

修法（`ui.jsx` 的 `useEnterGuard`）：以下任一条件成立时，Enter 只当输入法确认、不发送 ——

1. `compositionstart` 之后仍在组合中；
2. 键盘事件自带 `isComposing`；
3. `keyCode === 229`（部分浏览器/输入法组合期间只给这个码）；
4. `compositionend` 之后 120ms 内（Safari 会先发 compositionend 再发 keydown Enter，没有这个窗口会误发）。

会话栏与对比台的输入框都接了这个守卫；`Shift+Enter` 仍然换行。

验证：预览流程新增断言 —— 组合中派发 Enter 后草稿仍是原文、且不触发生成；随后正常按 Enter 能发送并进入流式输出。

## 0.9.5：框选配图修两个硬伤

用户反馈：框选框只能从最上方开始、框选出来的图很糊。

1. **只能从最上方开始**：`.pd-pdf-page` 没有 `position: relative`，绝对定位的选框是相对更外层容器算的，
   所以不管从哪拖，框都画在页面顶部。加上 `position: relative` 后坐标就对了。
2. **框选出来的图糊**：原来是从屏幕画布上 `drawImage` 裁 —— 那张画布只有"显示宽度 × 2"，
   框 160px 宽裁出来才 320px。改成**按 PDF 坐标重新渲染**：把框换算成 PDF 用户单位，
   用 `page.render({ viewport, transform })` 以 3x（上限 2600px）渲染这一块。
   实测框选 80% 页宽 ≈ **1600×1008**（原来同尺寸约 550×350）。
3. 顺带把拖动监听挂到 `window`：拖出页面边界不再中断（页面只有 ~260px 高，很容易拖出去），
   坐标按页面尺寸钳制；松手时用最终矩形提交。

验证：预览流程在真实 PDF 上框选并断言生成图宽度 ≥ 600px（实测 1600×1008）。

## 0.12.2：重新分析报"不是合法 JSON"的修复

用户重试 SemaCDR 时提示"模型返回的不是合法 JSON"。排查到三个原因，逐条修：

## 0.14.2：实验型论文的步骤串成一条链 + 长链排版折行（蛇形）

用户反馈："这篇论文流程图好诡异，不同于 SemaCDR 这种，是有步骤的，步骤应该是线性连通的呀，为什么不连在一起"。

根因在 `buildBlocks` 的后半段：步骤 / 现象 / 结论 / 结果**全都 `edges.push({from: principleId})`**，
于是每个节点都从「核心原理」射出去；自动整理按"图深度"分列，这些节点深度都是 1，
就被整整齐齐地摞成一列 —— 看起来就是一根竖着的刺猬，步骤之间当然没有线。

两处改动：

1. **串成链**：实验型（有 steps 或 phenomena）的流程改成
   `原理 → 步骤1 → 步骤2 → … → 现象1 → … → 结果1 → … → 结论`，
   每个节点只有前驱一条入边（smoke 新增两条断言：链存在、入边 ≤ 1）。
   cs 型（只有公式 + 结果）保持原样：公式仍挂在原理下面、结果从原理分叉（那是并列结论，不是步骤）。
2. **长链折行**：`flowLayout` 一条横带最多 6 列，超出的折到下一行并且**奇数带反向**（蛇形）。
   实测 9 个节点的实验流程：原来 9 列 = 约 3800px 的一条横线（适应视口后只有 20% 缩放），
   现在 6 + 3 两行、横向 2240px，缩放约 40%，步骤从右往左接着走，连线是一小段竖线。

两者叠加后，导入/重分析完就自动是"蛇形 + 线性步骤"的流程图；老论文需要点一次**重新分析**
才会用新规则重建连线（正文没动过的不必重新导入）。

     用 `redirect:'manual'` 读 Location 再从磁盘取，实测取到 4MB PDF）；
   - 写：`/zotero/note` 走官方 Web API（userID + API key），把 core 核与笔记写成一条 note；
   - 界面：论文库「从 Zotero 导入」列表（标题/作者/年份 + 导入），论文工具栏多出「回写 Zotero」（仅 Zotero 来源的论文显示）。
4. **PDF 视图记忆**：`paper.layout.pdf = { zoom, page }`，打开时恢复缩放并滚到上次那页；切页签/重进都不再重置。
5. **缩放卡顿**：连续缩放时先用 CSS `zoom` 拉伸已有位图（零重绘），停手 180ms 后才按新宽度重渲染一次。

预览台新增"切回原文后缩放不丢""文本层铺出""划词弹出翻译窗""Zotero 页签渲染"等断言。

## 0.16.1：移除翻译、文本选择对齐到行

用户要求：先把翻译功能去掉，文本选择要"选到哪就是哪"。

- **去掉翻译**：`POST /translate`、`chat.js` 的 `translateSelection`、客户端 `api.translate`、划词自动翻译小窗全部删除；
  划词后只保留「问这段 / 复制 / 关闭」+ 一小段选中内容预览。
- **选择对齐**：文本层的每一段改成**固定宽高盒子**（宽 = `item.width × CSS 缩放`，高 = 字号 × 1.18），
  不再用"字数 × 估算字宽"做 `scaleX` —— 估算偏大时盒子会盖住邻行/邻列，表现就是"一拖一大片"。
- **验证方法升级**：预览台用**真实鼠标拖选**一行（从行首拖到行尾），断言选中的字符串等于这一行各 span 的拼合；
  之前只是"合成一个 Range"再检查工具条是否出现，验不出坐标错位。

## 0.16.2：框选模式会把文本层藏起来（"文字选不了"的常见原因）

用户反馈 0.16.1 上"文本选择没有了"。用他的真实论文（WeaveRec PDF）在预览台跑真实鼠标拖选，
**选区是能出来的**（能选中行内文字，只是我的断言把上标/下标也算进"同一行"，字符串不一致）。

顺着排查发现一个真实的状态 bug：**「框选配图」开着时 `.pd-text-layer` 被 `display:none`**，
而 `picking` 状态挂在右侧栏、切走页签不会复位 —— 只要之前点过框选再切回来，整页文字就再也选不了，
光标也变成十字（容易被忽略）。

- 切走「原文」页签时自动退出框选模式；
- 文本层与 span 补上 `pointer-events: auto` / `-webkit-user-select: text`；
- 每个页面元素上加 `data-text-spans` 计数，便于排查"这一页到底铺没铺文字"。

## 0.16.3：复制拿到截图/弹窗闪断/工具条文本不对

三个症状同一个根因链：

1. **点「复制」窗口闪断** —— 关闭逻辑里判断的是旧类名 `.pd-selection-bar`，而工具条早改成了 `.pd-selection-pop`。
   于是**在工具条上按下鼠标就把选区清了**，React 立刻卸载按钮，`click` 根本没触发 → 弹窗消失（闪断）。
2. **复制出来是截图** —— 上一个 bug 导致 `selection.text` 在点击时已经不存在，`writeText('')` 失败/无操作，
   剪贴板里还是上一次复制的内容（你之前截的图）。
3. **工具条里文本不对** —— 用的是浏览器 `getSelection()` 的 **DOM 顺序**，双栏 + 上下标混排时会跳序
   （看到一行、复制出来却是别处的字）。

修法：

- 关闭判断改成 `.pd-selection-pop, .pd-selection-bar`，点工具条内部不再自我卸载；
- 复制加兜底：`clipboard.writeText` 失败时退回 `textarea + execCommand('copy')`（Electron 常见）；
- 新增 `collectSelectionText()`：取选区矩形 → 找相交的文本块 → **按先上后下、行内从左到右**重排，
  相邻块间隙大于 0.22 字宽时补空格 —— 这样工具条展示和复制的内容都按"你看到的顺序"拼。

验证：预览台用真实鼠标在**用户的 WeaveRec PDF** 上拖选，断言工具条文本包含该行首个词、且拦截
`navigator.clipboard.writeText` 后点「复制」能拿到同一段文字（之前这条断言根本过不了）。

### 0.2.0 修掉的问题：模型编造具体数值

实测发现：问「公式里的 λ 取多少」，模型答 `λ=0.4`，而论文原文是 `λ=400`（在正文第 37570 字符处）。
根因两条：

1. 导入时只把正文**前 26k + 后 4k 字符**送给模型，λ 所在的中段被整段丢掉；
2. 逐块提问只喂「标题 + 摘要 + 动机 + 该节点」，**正文根本没进上下文**，模型只能凭印象补。

0.2.0 的改法：

- 导入时整篇送进模型（≤80k 字符，超出才头尾切片），并把全文存进 `paper.json` 的 `text`（≤200k）；
- 逐块提问按问题检索全文最相关的段落（希腊字母 λ/θ 等归一化成英文名，中英文都能命中），摘录随问题一起进上下文；
- 系统提示词加硬约束：摘录里没有的具体数值/结论，必须说"给出的摘录里没有"，不许补数字；
- `GET /paper` 不再回传全文（只回 `textChars`），避免每次打开多传几十~几百 KB。
